# AI 文档体系 — 通用规则集

> 本文件是 ai-docs skill 的**可移植核心**：文档编写规则、类型模板、引用图机制、变更影响矩阵。与具体项目无关，任何项目通用。

---

## 一、文档编写总原则

1. **密集事实 > 叙述散文**：用表格 / 代码块承载事实，砍掉可推断的废话。
2. **字段级完整**：字段 / 参数 / 枚举列全（类型 / 必填 / 默认 / 含义），禁止"省略部分字段"。
3. **状态标记**：✅ 已实现 / 🚧 规划中 / 📝 草稿 / ❌ 已废弃。禁止把规划内容写成已上线。
4. **元数据头**：每份文档开头写 `版本 | 日期 | 状态 | 事实源`。

## 二、引用图机制（reference-map.md）

- 所有文档的引用关系**只在 `reference-map.md` 登记一处**（单一事实来源）。
- 每行一个文档，「引用」列记录其**上游**（它依赖谁）。
- **反向推导下游**：修改文档 X 时，grep「引用」列含 X 的所有行 → 这些是必须检查/同步的下游文档。

## 三、文档类型模板（固定引用结构）

| 文档类型 | 必须引用（上游） | 必须在哪个索引登记 |
|---------|----------------|-------------------|
| 表文档（02-db/tables/） | data-dictionary、conventions、所属模块设计 | 02-db/README 表清单 |
| API 模块文档（03-api/modules/） | common、对应设计文档、对应表文档 | 03-api/README 模块清单 |
| 设计文档（01-architecture/） | overview、相关表文档、相关 API 文档 | 01-architecture/README |
| 环境文档（04-environments/） | 对应配置（事实源）、seed 数据、相关 infra | 04-environments/README |
| 基础设施文档（05-infrastructure/） | 对应源码类 / 常量类（事实源）、相关设计 | 05-infrastructure/README |
| 层 README | 该层全部文档 | — |
| 根 README | 全部文档（索引） | — |

## 四、变更影响矩阵

修改代码后，按变更类型定位受影响文档：

| 变更类型 | 必须同步的文档 |
|---------|--------------|
| 修改接口（路径/参数/响应/错误码） | ① 对应 API 文档 ② common.md（若涉及通用约定） ③ 相关设计文档（若涉及规则） ④ 相关表文档（若涉及字段） |
| 修改表结构（列/索引/枚举） | ① 对应表文档 ② data-dictionary ③ 02-db/README 表清单 ④ migration（版本记录） ⑤ 引用该表的所有 API/设计文档（反向推导） ⑥ conventions（若新增通用约定） |
| 修改业务规则 | ① 相关设计文档 ② 相关 API 文档 ③ 相关表文档 |
| 修改配置/环境变量 | ① environments 对应文档 ② infrastructure 对应文档 ③ CLAUDE.md（若影响流程） |
| 新增模块 | ① 新设计文档 ② 新接口文档 ③ 相关表文档 ④ 根 README 模块地图 ⑤ 各层 README |
| 新增文档 | 见下方「新增文档流程」 |
| 修复已知缺陷 | ① 对应文档更新状态 ✅ ② 缺陷报告标记「已修复」 |

## 五、新增文档流程（四步登记）

1. **套类型模板**（第三节）确定必须引用的上游。
2. **在 reference-map.md 登记**一行（引用上游）。
3. **在根 README 完整索引 + 所属层 README 登记**。
4. **反向推导补链**：grep reference-map，为"应引用本新文档"的既有文档补链接。

> 完整 7 步（含套模板/补链/模块地图/元数据）见 [SKILL.md](SKILL.md) bootstrap 步骤 3-4。

## 六、新功能模块文档同步全流程清单

实现新功能模块触发「新增文档 + 修改文档 + 新增表文档」连锁。按序执行：

**A. 设计与表**
- [ ] ① 设计文档（若为规划模块，先在 planned 文档定稿）
- [ ] ② 表文档：表已存在则更新状态 🚧→✅；新增表则建表 SQL + 新表文档 + 登记表清单
- [ ] ③ 数据字典：字段/枚举有变 → 同步
- [ ] ④ 迁移记录：新增/改表 → 更新版本记录

**B. 接口**
- [ ] ⑤ 接口文档（已实现 / 规划中分目录）
- [ ] ⑥ 通用约定：新错误码/鉴权规则 → 更新 common.md

**C. 索引与引用图**
- [ ] ⑦ reference-map 登记全部新文档
- [ ] ⑧ 反向推导为既有文档补链
- [ ] ⑨ 根 README 模块地图（🚧→✅）与完整索引
- [ ] ⑩ 各层 README 登记

**D. 收尾**
- [ ] ⑪ 关联文档（安全/基础设施/环境）同步
- [ ] ⑫ 修复的已知缺陷在缺陷报告标记「已修复」
- [ ] ⑬ 新文档全部写元数据头

## 七、格式要求

### 元数据头模板

```markdown
> 版本：V1.0 | 日期：YYYY-MM-DD | 状态：✅ 已实现 / 🚧 规划中 / 📝 草稿
> 事实源：<文件路径，数据以此为准>
> 关联文档：<可选>
```

### 常用表格模板

**字段 / 参数：** `| 字段 | 类型 | 必填/空 | 默认 | 含义 |`
**枚举：** `| 值 | 常量 | 含义 | 触发条件 |`

### 关键规则

- 单份文档建议 ≤ 500 行；过长拆子文件。
- 同会话内改代码 + 同步文档（利用上下文缓存，省 token）。
- 只更新变更处，不整篇重写；小改不动版本号。
